# Blue Ocean Market V30.45.0 — Unified Action Feedback

## Protected source and release scope
Built directly from the verified V30.44.0 source archive, retaining V30.40–V30.44 access, Tasks, Finance correction, Accounting account drill-down, statement/PDF, and transfer workflows and the V30.39.x performance foundation. Presentation-only release; no database schema, API contract, permission, idempotency or persistent-disk changes.

## Root cause and targeted changes
1. V30.14 `api()` had a full-screen processing overlay and button spinner for every mutation; V30.38.2 added a modal processing chip; V30.39 added a network banner plus a separate button state. One payment could show all these simultaneously.
2. `public/v345-client.js` installs one shared `window.BOMFeedback` coordinator: ordinary mutations use one button state, important transactions use one modal/section overlay with disabled origin button, and reset/restore/maintenance use one full-screen overlay. Concurrent same-host transactions share one visible surface; slow guidance replaces the message in place. Local EN/KR strings and accessible `aria` states are included.
3. The **served** `public/runtime-v30392.js` V30.14 mutation wrapper delegates feedback presentation to that coordinator while retaining Review & Confirm, idempotency keys and `try/finally` cleanup. Original action context is no longer overwritten by clicking the Review & Confirm dialog.
4. V30.38.2 modal close/child-state workflow is preserved; only its competing processing chip is suppressed when the new coordinator is loaded. V30.39 request counting, GET deduplication, lifecycle and diagnostics remain; action-triggered direct fetches now request the shared coordinator’s one button-level surface, while its redundant global banner is suppressed. A direct read in flight is visually superseded by a later important transaction on the same button without weakening either request lifecycle.
5. `toast()` presents one relevant completion and deduplicates equivalent or repeated same-operation success/progress messages while allowing contextual errors. No business-state success is generated by the coordinator itself.
6. Versioned served scripts, precompressed changed assets and package/server/health identity advance to V30.45.0; V30.44 client stays loaded before the new small extension.

## Deliberately not changed
Historical patch/observer removal, canonical module redesign, unconverted pagination, SQL N+1 cleanup, bounded request scheduling and multi-user Render testing remain in the performance backlog. Do not promote a small feedback point release as full performance-program completion. API-led mutations and action-triggered direct fetches share the coordinator. Remaining unrelated historical observers and data-list optimization are still pending.

## Verification
`npm run qa:v345`, `npm run qa:v344`, `npm run qa:v343`, `npm run qa:current`, `npm run qa:render` and asset/ZIP integrity. Authenticated interactive Render testing requires deployment and live account access and is not claimed as performed in the offline build environment.
