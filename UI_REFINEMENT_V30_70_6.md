# V30.70.6 — UI consistency and daily workflows

Built directly from V30.70.5. No framework replacement, permission changes, ledger recalculation, schema migration, Git push or deployment.

| Review point | Implementation |
| --- | --- |
| Page headers | One visible record/form title; contextual Back toolbar retains the original hidden reference title used by nested workflow navigation. |
| Imports search | Removed legacy page-only filter injection. One server-owned search/status/sort/direction/reset toolbar. Sort and search restore on refresh; ordering keys are whitelisted before SQL. |
| Action hierarchy | Import operational buttons remain visible. Permission-derived Cancel/Void/Delete are in a separate record-controls section below history. |
| Profiles | Common summary cards, money alignment, section tabs and action sizing apply to supplier/customer/employee layouts. Existing balance categories and recent customer redesign retained. |
| Payments | Three sections for payment source, recipient/amount, and evidence/reference. Existing optional fee disclosure and live settlement calculations retained. Removed an older cash-rule decorator from this owned form to prevent duplicated required markers and conflicting labels. |
| Tables | Consistent numeric alignment, visible row controls, compact pagination and labeled mobile records for operational lists. Dense financial tables retain scrollable table layouts. |
| Finance/Accounting | Finance review actions and financial-record browsing have separate labeled groups. Accounting summary styling is quieter; posting/verification/payment semantics remain distinct. |
| Mobile/HR | Scrollable section navigation and 44px employee tab targets. Operational record cards retain all displayed values and actions. |
| Dashboards | Primary metric row remains prominent; secondary metrics are smaller and quieter, with an explicit KRW financial-figure label. No analytics or new calculations added. |
| Settings | Company, Money, People & access, System categories show one subsection group. Key-based active state supports intercepted bank/file settings and refresh. Version label now comes from package.json. |
| POS | Larger menu targets, explicit KRW prices, sticky desktop basket, responsive layout, accessible quantity/price labels, and live basket total. Existing order/payment actions retained. |
| Other screens/feedback | Compact notification/audit filters; approval rule configuration is a secondary disclosure. Success formatting delegates through the existing coordinator so one mutation does not produce multiple different success notices; errors remain visible. |

## Validation

See `qa/evidence/ui706-browser.json`, `qa/evidence/ui706-matrix.json`, and `qa/evidence/postgres-release.json` for actual results. Run with Node 22. Browser checks accept `BOM_CHROMIUM`; server PDF checks use `CHROME_PATH`.

- `node qa/postgres/ui706-browser.cjs`: interaction checks against disposable fixture data.
- `node qa/modernization/ui706-matrix.cjs`: desktop, 390px mobile and Korean screens; screenshots are optional via `BOM_UI_SCREENSHOTS` and are not part of this release.
- `npm run qa:release`: existing PostgreSQL-compatible workflow, upgrade, PDF and regression gate.

Local fixture QA does not certify the hosted deployment or every possible role/status combination.

QA environment note: the supplied headless-shell CLI cannot print PDFs directly in this host. The affected export suites were rerun using real Chromium through its browser PDF API; production export code was unchanged. Detailed retry notes remain in the regression evidence.

Final result: PASS — 31 regression suites / 500 workflow checks, 20 database and upgrade tests, 13 UI interaction checks, 61-screen matrix, and 346 JavaScript syntax checks. Additional payment/POS/Korean captures showed no body overflow. No hosted deployment or Git changes were performed.
