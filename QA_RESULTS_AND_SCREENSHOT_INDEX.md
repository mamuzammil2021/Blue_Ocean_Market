# QA results and screenshot index — V30.69.40 completion

## Release decision

**Ready for controlled staging acceptance.** The source implementation and available automated checks are complete. The consolidated release gate passes all 15 aggregate entries on Node 22.21.0. No production deployment, live data mutation, outbound user messaging, remote push or main-branch modification occurred. Target-host installation/PDF validation and business-owner acceptance are required before production.

The completion pass fixes the audited Korean label backlog, converts the two Accounting detail destinations to full pages, consolidates their renderers, restores the sales list, and fixes rapid keyboard dialog focus. Uncertain compatibility scripts/styles remain intentionally retained under the brief's safe-cleanup policy. This is not a claim of zero possible regressions or full WCAG certification.

## Functional coverage

Passing suites exercise packaging catalogue, multi-line purchases, decimal totals, supplier eligibility, approvals, partial receiving, stock/production usage and cart/history. They also exercise KRW/USD/PKR and cross-currency settlement, actual account debit versus invoice valuation, advances as non-cash, original references in corrections, verified locks, approval-before-Finance verification, exact-account posting, failed writes/rollback, duplicate/retry guards, and Excavator regressions. Product browser checks cover English/Korean/Both editing, save/reopen, family/lot pages, unsaved production guards, completion, traceability and mobile action visibility. Per-suite evidence accompanies the release.

The baseline's earlier 12→14 journal-count finding was a QA race with queued proposals for prior Finance rows. Waiting for prior queue work resolved it; Accounting business logic was not changed. The follow-up sales-list fault was a caught UI ReferenceError from a copied allocation fragment, not a stored-data repair.

## Production handoff limits

The remaining release gates require the deployment environment: standard target-host install/start, normal Chrome CLI PDFs with Korean fonts, real-volume performance and business-owner acceptance. This host's direct Chrome CLI PDF timed out; actual PDF regression tests pass through a QA-only Playwright CLI adapter, which is not shipped as a production dependency. No live Render/Docker deployment was performed.

Browser AX-tree inspection is evidence for programmatic labels, not OS screen-reader certification. Every possible record lifecycle/role combination, native browser zoom implementation and assistive-technology combination is not claimed. All discovered route patterns have representative six-way coverage. These limits are disclosed rather than turned into an unsupported production-ready claim.
